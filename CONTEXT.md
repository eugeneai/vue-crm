# Глобальный контекст разработки

## 🎯 Основные принципы

### **Генерация только запрошенных компонентов**
**ВАЖНО**: При разработке генерировать ТОЛЬКО те компоненты/модули/файлы, которые явно запрошены разработчиком. Не создавать дополнительные файлы "на будущее" или "для полноты".

### **Архитектурный стек**
- **Frontend**: Vue.js 3.0 + Composition API + TypeScript + GraphQL Client
- **Backend**: Pyramid + SQLAlchemy 2.0+ + Graphene (GraphQL) + SQLite
- **Архитектура**: MWWM (Model-View-ViewModel-Worker-Model)
- **Шаблоны**: Chameleon (для серверного рендеринга при необходимости)

## 📋 Бизнес-логика

### **Сущности**
1. **Contact (Контакты)**
   - ФИО (обязательно)
   - Место работы (опционально)
   - Телефон (опционально)
   - Email (опционально)

2. **Meeting (Встречи)**
   - Связь с Contact (обязательно)
   - Дата и время (обязательно)
   - Тема (обязательно)
   - Место (опционально)

3. **Note (Заметки)**
   - Связь с Meeting (обязательно)
   - Дата (обязательно)
   - Текст заметки (обязательно)

### **Процессы**
- Регистрация всех встреч и важных событий
- Управление контактами и их историей взаимодействий
- Добавление заметок к встречам (НЕ к контактам напрямую)

### **Выходные документы**
1. 📅 Список предстоящих встреч на неделю с указанием контактов и тем, отсортированный по дате и времени
2. 📋 Для заданного контакта выдать историю всех встреч и заметок, отсортированную по дате

## 🏗️ Технические требования

### **Frontend (Vue.js 3)**
- Использовать **декларативный подход** Vue 3
- **Composition API** вместо Options API
- **TypeScript** для строгой типизации
- **GraphQL Client** (Urql или Apollo) для связи с бэкендом
- **Pinia** для управления состоянием
- **Компонентный подход** с переиспользуемыми компонентами

### **Backend (Pyramid)**
- **Pyramid** как веб-фреймворк
- **SQLAlchemy 2.0+** с async поддержкой
- **Graphene-Python** для GraphQL эндпоинтов
- **SQLite** как легковесная БД
- **Alembic** для миграций

### **База данных**
- **SQLite** файловая база данных
- **SQLAlchemy ORM** для работы с БД
- **Индексы** на часто используемых полях
- **Каскадное удаление**: Contact → Meeting → Note

## 🔧 Конвенции разработки

### **Именование файлов**
- **Vue компоненты**: `PascalCase.vue` (ContactList.vue, MeetingForm.vue)
- **TypeScript файлы**: `camelCase.ts` (contactStore.ts, meetingQueries.ts)
- **Python модули**: `snake_case.py` (contact_model.py, meeting_schema.py)
- **GraphQL**: `camelCase` для полей, `PascalCase` для типов

### **Код стайл**
- **Frontend**: ESLint + Prettier конфигурация
- **Backend**: Black + isort + flake8
- **TypeScript**: Строгая типизация, интерфейсы для всех GraphQL типов
- **Python**: Type hints, docstrings

### **Коммиты**
Использовать Conventional Commits:
- `feat:` Новая функциональность
- `fix:` Исправление ошибки  
- `docs:` Изменения в документации
- `refactor:` Рефакторинг кода
- `test:` Добавление тестов

## 🚀 Процесс разработки

### **1. Анализ требования**
- Четко определить, какие именно компоненты/файлы нужны
- Проверить существующую структуру проекта
- Определить зависимости и связи

### **2. Создание только необходимого**
- **НЕ создавать** лишние файлы "на всякий случай"
- **НЕ добавлять** не запрошенную функциональность
- **Следовать** существующим паттернам и конвенциям

### **3. Интеграция**
- Проверить совместимость с существующим кодом
- Убедиться в правильности импортов и зависимостей
- Протестировать взаимодействие компонентов

### **4. Документация**
- Обновить соответствующие `.md` файлы при необходимости
- Добавить комментарии к сложной логике
- Указать на изменения в архитектуре
