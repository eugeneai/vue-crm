# .gitignore для проекта личной CRM

## 📋 Обзор

Файл `.gitignore` настроен для проекта со стеком:
- **Frontend**: Vue.js 3 + TypeScript + Vite
- **Backend**: Python + Pyramid + SQLAlchemy + SQLite
- **Инфраструктура**: Docker, виртуальные окружения

## 🎯 Что игнорируется

### **Обязательно игнорируется:**
- `node_modules/` - зависимости фронтенда
- `venv/`, `.venv/` - виртуальные окружения Python
- `__pycache__/`, `*.pyc` - кэш Python
- `dist/`, `build/` - скомпилированные файлы
- `.env`, `.env.*` - файлы окружения с секретами
- `*.log` - логи приложений
- `.DS_Store`, `Thumbs.db` - системные файлы

### **Базы данных:**
- `*.db`, `*.sqlite` - **исключаются по умолчанию**
- `database/contacts.db` - **разрешена** (основная БД проекта)
- `database/production.db` - **разрешена** (production БД)
- `database/test*.db` - **разрешены** (тестовые БД)

### **IDE и редакторы:**
- `.vscode/` - **исключается**, кроме:
  - `.vscode/extensions.json`
  - `.vscode/settings.json`
  - `.vscode/tasks.json`
  - `.vscode/launch.json`
- `.idea/` - полностью исключается

## 🔧 Настройка для разработчиков

### **Для нового разработчика:**
1. Клонировать репозиторий
2. Создать виртуальное окружение: `python -m venv venv`
3. Установить зависимости: `pip install -r backend/requirements.txt`
4. Создать `.env` файл (на основе `.env.example` если есть)

### **Добавление новых исключений:**
Если нужно добавить новый тип файлов в .gitignore:
1. Определите категорию (Frontend/Backend/Общие)
2. Добавьте правило в соответствующий раздел
3. Убедитесь, что исключения идут после общих правил

## ⚠️ Важные моменты

### **Порядок правил:**
1. Общие правила исключения (`*.db`)
2. Конкретные исключения (`!database/contacts.db`)

### **Базы данных в репозитории:**
- `contacts.db` - включена в репозиторий для демонстрации структуры
- В production рекомендуется НЕ хранить БД в репозитории
- Для тестов используйте `test*.db` файлы

### **Файлы окружения:**
- Никогда не коммитьте `.env` файлы
- Создайте `.env.example` с шаблоном переменных
- Каждый разработчик создает свой `.env` локально

## 🚀 Быстрые команды

### **Проверка игнорирования:**
```bash
# Проверить, игнорируется ли файл
git check-ignore путь/к/файлу

# Показать все игнорируемые файлы
git status --ignored
```

### **Добавление игнорируемого файла (при необходимости):**
```bash
# Принудительно добавить игнорируемый файл
git add -f путь/к/файлу
```

### **Очистка кэша .gitignore:**
```bash
# Если .gitignore не работает как ожидается
git rm -r --cached .
git add .
```

```
# Общие системные файлы
  - Операционные системы
  - Временные файлы
  - Логи

# Frontend (Vue.js 3 + TypeScript + Vite)
  - Зависимости (node_modules/)
  - Сборка (dist/, build/)
  - Кэш

# Backend (Python + Pyramid + SQLAlchemy)
  - Python кэш (__pycache__/)
  - Виртуальные окружения (venv/)
  - Пакеты и дистрибутивы

  - Общие правила (*.db)
  - Исключения (!database/contacts.db)

# IDE и редакторы
  - VS Code (.vscode/)
  - IntelliJ IDEA (.idea/)

# Конфигурация и секреты
  - Файлы окружения (.env)
  - Секретные ключи

# Дополнительные файлы
  - Графические файлы
  - Документы
  - Архивы
```

## 🔄 Обновление .gitignore

При добавлении новых технологий в проект:
1. Добавьте соответствующие правила в существующие разделы
2. Или создайте новый раздел, если технология существенно отличается
3. Протестируйте с `git check-ignore`
4. Обновите эту документацию при необходимости
